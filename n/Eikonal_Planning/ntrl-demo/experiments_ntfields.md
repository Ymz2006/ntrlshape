# Experiments -- NTFields on the 3-D and 2-D shape tasks

> Collected at the repository root. Every unqualified path below (`datasets/`, `Experiments/`, `outputs/`, `results/`, `tests/`, `train/`, ...)
> is relative to `baselines/NTFields_minimal_working/`, where this table's runs live. Regenerate with `python make_experiments_md.py` from that directory.

Trained with `train_3dshape_all.sh` (4000 epochs x 5 batches of 2000 per environment -- the same 20,000 optimizer steps the ntrl-demo baselines get) on the same datasets as the main repo's `experiments_ours.md`.

Rows fall in two blocks. The **3-D section** is SE(3) over `env1`-`env4`; the
**2-D section** is SE(2) over the four planar mazes `2denv1`-`2denv4` (12, 13, 6
and 8 bodies, 350 x 350 each), seven shapes apiece, generated by
`preprocess_obj.py --2d`. The 2-D data is stored in the same 6-D SE(3) layout
with `z`, `rx`, `ry` pinned to 0, so the same network, trainer and columns apply
unchanged. `Tshape3d_2denv4` was trained under the pre-env-tag name
`Tshape3d_env4` and renamed on 2026-09-12, when the SE(3) `Tshape3d_env2..4`
cells were trained; the `Tshape3d_env*` rows of the 3-D block are all SE(3).
All 28 2-D datasets exist, with both test-set variants -- standard
(`--offset 0.02`) and `_tight` (`--offset 0.005`) -- see `../../2d_gen_times.md`.

The table is split into a 3-D and a 2-D section. Every cell of the benchmark
gets a row, trained or not. A row whose `Model` is
`--` has no epoch-4000 checkpoint yet; if its `Train Time (s)` is filled while
`Model` is still `--`, that is a run currently under way, and the figure is
elapsed-so-far rather than final. `Train Time (s)` is the training time of that
cell, parsed from `<modelPath>/logs/<env>.log`.

The columns are laid out like `experiments_metric_ntfields.md`, which tabulates
`baselines/ntrl-demo`'s `models/metric` over the same environments and the same
test sets, so the two tables can be read row by row.

`Valid` counts pairs whose rollout reached the goal AND stayed collision-free at
every waypoint, and comes from `3d_plan.py`: the 1000 start/goal pairs of
`../../ntrl-demo/ntrl-demo/testing_data/3dshape/<env>` planned with the MPPI
controller of `ntrl-demo/evaluate_training_3d.py` driven by this checkpoint, one
path at a time. A pair converges when the rollout reaches the 0.01 goal ball
inside 200 steps; collision is `preprocess_obj`'s point-in-tet test against a
50k-point sampling of the whole environment mesh, walls included. Unlike the
`experiments_metric_ntfields.md` runs, nothing is screened out beforehand for an
endpoint that already collides, so the denominator here is the full test set and
those already-colliding pairs count against NTFields.

`Plan Time` is the per-case wall clock of the rollout over all scored cases;
`Path Length` is OMPL's SE(3) metric (`sum ||dt|| + acos(|q.q'|)`) over the
successful ones -- the same two quantities `experiments_rrt_connect.md` reports,
measured the same way. Note that `experiments_metric_ntfields.md` reports its
length in the plain Euclidean 6-D configuration metric instead, so only the
`Valid` and `Plan Time` columns are directly comparable between the two tables
(this table's `cfg_length_mean`, in each `plan_summary.txt`, is the matching
Euclidean number).

`Valid (tight)` is the same measurement on the `<env>_tight` test sets, which
`dataprocessing/make_tight_testing_data.py` regenerates at `--offset 0.005`
instead of 0.02: start and goal poses may sit four times closer to obstacles, so
the queries are harder. The checkpoint is unchanged -- it is the model trained on
the ordinary set, re-evaluated. Per-set timing and length for those runs are in
`./outputs/3dplan_tight/<env>_tight/plan_summary.txt`; those timings ran three jobs to a GPU, so
read them as amortized, not against the `Plan Time` column, whose runs had a GPU
each. Success is unaffected -- the rollout is deterministic given `--seed`.

NTFields replays an epoch whose mean loss exceeds `--repeat-ratio` times the
previous one, measured against a `prev_diff` that starts at 1.0. The 6-D shape
data starts near 2.0, so the shipped 1.2 rejects epoch 1 forever; these runs use
a relaxed 2.5 with a 20-replay cap. Losses are therefore not comparable in scale
to the ntrl-demo tables -- the loss functions differ (NTFields is isotropic and
ignores `normal.npy`).

## 2-D section &mdash; SE(2), `2denv1`-`2denv4` x 7 shapes

All four planar mazes, all seven shapes: 28 cells. `Training Time` is the same
measurement as `Train Time (s)` written as h/m/s, so a row can be read without
converting. `Tshape3d_2denv4` was trained from the then-named
`datasets/3dshape/Tshape3d_env4` (now `Tshape3d_2denv4`); its checkpoint and
plan dirs were renamed to match on 2026-09-12.

Both planning passes ran through `_run_2d_plan_ntfields.sh`, which forces
`3d_plan.py --2d`: the MPPI displacement is masked to (x, y, rz) before the
magnitude clamp, so z / rx / ry hold their start value of 0 for the whole
rollout. The flag is redundant with the `"two_d": true` each 2-D `meta.json`
already carries -- passing it makes the mode explicit in every log.

`rectangle_2denv3` is a **failed fit, not a hard cell**: its final loss is
1.7641e+00 against 0.51-0.75 for every sibling and never descended past epoch
1, and it plans 47.8% in the env where the other six shapes reach 98.5-100%.
Read that row as a training failure pending a retrain, not as a method result.

## 3D_1k_valid

The same SE(3) cells as the 3-D section above -- same checkpoints, same
`3d_plan.py`, same controller settings, same 1000 cases -- scored on
`../../ntrl-demo/ntrl-demo/testing_data_1k_complete/3dshape/<cell>` instead of
`testing_data/`.  Every pair in that set is collision-free *and* carries an
RRT-Connect path found within 180 s, so unlike the table above it has a
demonstrated 100% ceiling: a failure here is the planner's, not a start/goal
pair that nothing could solve.

Because the unsolvable pairs are gone, these numbers are **not** comparable
row-for-row with the 3-D section -- the two are different test populations,
not the same test measured twice.  See `testing_data_1k_complete/README.md`
for how the set was built and what fraction of sampled pairs it discarded.
`Lcouch_Corozal` has no 1k set and is absent.  `Tshape3d_env2..env4` were
trained 2026-09-12 on the SE(3) `datasets/3dshape/Tshape3d_env*` sets and have
no `testing_data/` run, only this one.

`Valid`, `Plan Time` and `Path Length` are the same three measurements as the
3-D section (full-denominator success, per-case rollout wall clock, OMPL SE(3)
length over the successes).  `Trans Length` and `Rot Length` split that same
length the way `experiments_rrt_connect.md` does: translation travelled
(`sum ||dt||`, normalized frame) and rotation travelled as the geodesic angle
in radians (`sum 2*acos|q.q'|`), so `Path Length = Trans + Rot / 2`.  These
runs went four to two GPUs, so read the timings as amortized.  `test_cases` is
the number of pairs scored.

Produced by `_run_plan_1k_ntfields.sh`; summaries in `./outputs/3dplan_1k/<cell>/plan_summary.txt`.
